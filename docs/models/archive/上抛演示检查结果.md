# 上抛演示网页检查结果：公式自洽，主要需统一 g 与增强教学表达

## 检查结论
我通读了 `demo/vertical-throw-demo.html`（竖直上抛运动演示），并对照了仓库里已有的 `平抛演示检查结果.md`。

**核心结论：物理公式与数值口径是自洽的，没有平抛那页“标签与数值口径矛盾”的问题。** 真正需要修改完善的，主要是**跨文件的 g 取值不统一**，以及若干**教学表达增强点**。JS 语法已用 `node --check` 校验通过，无运行时隐患。

---

## 1. 物理公式核对（均正确）

| 量 | 公式 | 核对 |
|---|---|---|
| 高度/位移 | `y = v₀t − ½gt²` | ✓ 向上为正 |
| 速度 | `v = v₀ − gt` | ✓ 上升为正、下落为负 |
| 飞行总时间 | `T = 2v₀/g` | ✓ 落回抛出点 |
| 最大高度 | `H = v₀²/2g` | ✓ 顶点处 v=0 |
| 落地速度大小 | `|v| = v₀` | ✓ 与初速等大反向 |
| v-t 图斜率 | 恒为 `−g` | ✓ 直线 |

坐标约定：以竖直**向上为正**、从地面（抛出点）起算 `y=0`。在这个约定下，“高度 y”恰好等于“从抛出点的位移 s”，因此 `s-t` 图就是 `y-t` 图——**自洽，无歧义**。

---

## 2. 与平抛页的对比（本页是优点）

平抛页 `projectile-motion.html` 里 `y = h − ½gt²` 却标“竖直位移 y”，造成“标签与数值口径矛盾”（详见 `平抛演示检查结果.md`）。

**本页不存在该问题**：因为抛出点就在地面，`y` 从 0 起算，“高度 y”=位移 s，文字标签与计算口径一致。这一点应保持，转发给学生不会误判为公式写反。

---

## 3. 需要修改 / 完善的地方（按优先级）

### P0 — 一致性问题（建议一定改）
- **g 取值不统一**：本页固定 `g = 10 m/s²`，而同仓库 `projectile-motion.html`（平抛）用的是 `g = 9.8`（见其检查结果 `sqrt(2*220/9.8)`）。同一套教学演示里重力加速度不一致，容易让学生混淆。
  - 建议：全系列统一为 `9.8`，或在参数区加一个 **「g 切换 9.8 / 10」** 开关（高中常简化为 10，大学用 9.8，加开关最稳妥）。

### P1 — 教学表达增强（建议加）
- **增加“上升时间 / 下落时间”分段显示**：上抛的对称性（`t↑ = v₀/g`，`t↓ = v₀/g`，两段相等）是重点，当前只在 v-t 图里隐含，建议实时数值区加一行“上升时间 t↑ = v₀/g”。
- **增加键盘 / 快捷控制**：空格 = 播放/暂停、R = 重置、可选逐帧步进，便于课堂边讲边停。
- **图例补一句说明**：加速度箭头长度几乎恒定（约 32–35px），而速度箭头随 v₀ 变化（17–130px）。这其实是正确的“a 大小恒定”表达，但视觉上容易误以为 a 在变。建议在图例注明“加速度箭头长度固定 = 大小恒定”。
- **落地标记文字**：当前画的是 `落地 v = -v₀`，与读数“落地速度（大小 = v₀）”一致，可保留；若加 g 开关，这两处要跟着变量走（目前 `landVel` 用 `v0Of()`，已跟随初速，不受影响）。

### P2 — 健壮性 / 体验（可选）
- **初速度下限**：滑块 `min=5`，若想演示更慢更小的上抛，可下探到 1–2 m/s。
- **播放速度上限**：当前 `max=2×`，可提到 4× 方便快速过场。
- **加速度读数**：`elAcc` 用 `'-' + g.toFixed(2)`，已跟随变量 `g`，开放改 g 时不用动，✓ 无需改。
- **移动端**：窄屏下矢量文字标签（v / a）可能略拥挤，小屏可隐藏部分标注。
- **HTML 初值写死**：`elVel` 初始写 `20.00 m/s` 与默认 v₀=20 一致，`reset()` 会覆盖；若改默认 v₀ 需同步，影响极小。
