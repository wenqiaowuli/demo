# 需求：共点力平衡演示 v3（移动端窄屏适配修复）

> 在 v2（`requirement-force-equilibrium-v2.md`）基础上修复移动端显示缺陷。未提及的部分（交互模型、物理模型与公式、图表、按钮状态矩阵、v1/v2 验收中未被本文件修订的条款）维持不变。

## 背景与问题
- 安卓手机访问时，演示窗口中"小球在水平拉力状态下缓慢运动"的画面完全没有出现（画布空白，仅图表与面板正常）。
- 根因：主场景画布按 880×520 固定设计坐标绘制（悬点、绳长、比例尺、提示文字均硬编码），`setupCanvas` 仅做 DPR 缩放、未做"画布宽度→设计坐标"的适配缩放。手机视口宽约 360–414 px，可见区域约 360×212 逻辑像素，而小球路径范围 x∈[330, 555]、y∈[70, 330]，初始即位于可见区之外，整个拉动过程画在屏幕外。桌面端宽度 ≥880 px 时坐标恰好铺满画布，故问题只在窄屏暴露。

## 修订清单

### R1 场景整体等比缩放（方案 A）
- 场景画布维持 880×520 设计坐标系与全部既有绘制逻辑不变；`setupCanvas` 对场景画布叠加等比缩放 `fit = cssWidth / 880`（CSS `aspect-ratio` 已锁定 880/520 宽高比，等比缩放即可完整覆盖）。
- 变换矩阵为 `setTransform(dpr·fit, 0, 0, dpr·fit, 0, 0)`；`clearRect` 与比例尺、提示文字等以 `BASE_WIDTH/BASE_HEIGHT` 为锚的元素统一落在设计坐标系内，不再使用实际 CSS 宽高。
- 两幅曲线图维持现有自适应绘制方式（按实际 CSS 宽高绘制）不变。

### R2 场景文字可读下限
- 场景内文字（T/F/G 矢量标注、θ 角、初始位置、顶部状态与提示、比例尺）经 `sceneFont(size, bold)` 输出：实际字号 = 设计字号 × fit，且补偿至不低于 10 px 的可读下限。
- 窄屏（fit < 0.75）时右上提示文字换行至第二行（y=46）避让左上状态文字，避免下限补偿后文字变"相对更宽"导致的同行重叠。

## 验收标准
1. 手机视口（390×844，DPR 2）：初始态小球竖直悬挂于画布内可见，T、G 箭头与标注完整；自动演示过程中小球沿弧缓慢上移全程可见（θ 中途约 20° 时 T、F、G+F=−T 辅助均可见）；结束后停在目标角 45°，构图完整。
2. 窄屏下场景文字实际字号不低于 10 px；初始态左上状态文字与右上提示不重叠（提示换行至第二行）。
3. 桌面视口（≥880 px）：画面与修复前一致（fit=1，提示仍在第一行），无回归。
4. 两幅曲线图、实时数值面板、按钮/滑条交互行为与 v2 验收一致，不受本次改动影响。
