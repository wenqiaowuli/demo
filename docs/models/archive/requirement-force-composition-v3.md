# 需求：力的合成与分解演示 v3（移动端窄屏适配修复）

> 在既有版本基础上修复移动端显示缺陷。未提及的部分（双模式交互、物理模型与公式、平行四边形定则/分解作图、图表、按钮状态矩阵、拖拽约定）维持不变。修复方法与 `requirement-force-equilibrium-v3.md`（共点力平衡 v3）完全同法。

## 背景与问题
- 安卓手机访问时，主演示窗口画面不能在屏幕中显示（场景画布几乎空白），仅曲线图与下方面板正常。
- 根因：主场景画布按 880×520 固定设计坐标绘制——`makeTransform` 以 `BASE_WIDTH/BASE_HEIGHT` 为可用区求缩放平移，网格、坐标轴、矢量、角弧、标注全部落在 880×520 设计空间（内容居中于设计点约 (440, 260)）；而 `setupCanvas` 仅做 DPR 缩放、未做"画布宽度→设计坐标"的适配缩放。手机视口宽约 360–414 px 时，可见区域仅约 362×212 逻辑像素，场景原点 O（设计坐标 x≈440 附近）及绝大部分内容落在可见区之外。桌面端宽度 ≥880 px 时坐标恰好铺满画布，故问题只在窄屏暴露。
- 本页拖拽交互 `scenePos` 本就把手势坐标映射到 0..880 设计空间，因此补上等比缩放后拖拽自动对齐，无需改动。

## 修订清单

### R1 场景整体等比缩放（方案 A）
- 场景画布维持 880×520 设计坐标系与全部既有绘制逻辑（含 `makeTransform` 自适应变换、拖拽交互）不变；`setupCanvas` 对场景画布叠加等比缩放 `fit = cssWidth / 880`（CSS `aspect-ratio` 已锁定 880/520 宽高比）。
- 变换矩阵为 `setTransform(dpr·fit, 0, 0, dpr·fit, 0, 0)`；`drawScene` 的 `clearRect` 改为整块设计区（-1,-1,882,522）；比例尺、顶部状态/提示、banner 等以 `BASE_WIDTH/BASE_HEIGHT` 为锚的元素统一落在设计坐标系内。
- 两幅曲线/条形图维持现有自适应绘制方式（按实际 CSS 宽高绘制，仅 DPR 缩放）不变。

### R2 场景文字可读下限
- 场景内文字（F₁/F₂/F 矢量标注、θ/φ/α 角弧、方向线 φ₁/φ₂、O 点、比例尺、红色 banner、顶部状态与提示）经 `sceneFont(size, bold)` 输出：设计空间字号取 max(设计字号, 10/fit)，等比缩小后屏上实际不低于 10 px。
- 窄屏（fit < 0.75）时顶部右侧提示（合成模式"待机时可拖拽 F₁/F₂…"、分解模式"待机时可拖拽方向线手柄…"）换行至第二行（y=46），"不可分解"红色 banner 下移至 y=62，避让左上状态文字。
- 曲线/条形图（`ctxL`/`ctxR`）字体不在本次补偿范围内，维持原尺寸。

## 验收标准
1. 手机视口（390×844，DPR 2）：合成模式——待机（F₁=4、F₂=3、θ=60° 的平行四边形构图）与自动演示扫描过程中矢量、辅助线、角弧、标注、比例尺均完整可见；分解模式——正交分解、按两已知方向两种作图同样完整可见。
2. 窄屏下场景文字屏上实际字号不低于 10 px；顶部状态与提示不重叠（提示换行至第二行）。
3. 手机端待机拖拽手柄（F₁/F₂ 端点、方向线手柄）命中与桌面一致（`scenePos` 映射不变，已实测 F₂ 端点拖动生效）。
4. 桌面视口（≥880 px）：画面与修复前一致（fit≈1，提示仍在第一行），三矢量正常渲染，无回归。
5. 两幅曲线/条形图、实时数值面板、按钮/滑条/模式切换行为与既有验收一致，不受本次改动影响。
