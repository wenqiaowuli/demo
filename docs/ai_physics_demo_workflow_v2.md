# 高中物理模型动画网页制作流程 (v2.1)

> **v2.1 修订记录**（2026-10-19）：第 6 节目录结构对齐仓库现状——模型单页 `*.html` 与其测试脚本平铺于项目根目录，不再要求 `models/` 子目录；`_repo/` 明确为独立发布同步仓库、不纳入本仓库追踪。其余流程机制沿用 v2.0。

## 1. 目的与适用范围

本流程用于依照人教版高中物理六册模型清单，制作“一页一个模型”的交互式动画演示网页。制作目标是**物理严谨正确、教学重点突出、交互稳定可验、跨端体验流畅**，并能按现有项目规范高效登记与发布。

本工作流固定模型版本和各阶段权责；针对模型复杂度引入**分级通道（Tiered Workflow）**，在保持高质量物理把关的前提下大幅提升批量吞吐效率。如果指定模型暂不可用，先记录并请用户确认替代型号，不自行静默更换。

## 3. 模型复杂度分级通道 (Tiered Workflow)

为避免所有模型均套用冗长链路导致吞吐受阻，在阶段 0 完成后依据物理与状态复杂度划分为两级通道：

```
[模型选题 (阶段 0)]
        │
   复杂度评估
   ┌────┴────────────────────────┐
   ▼                             ▼
【Tier 1：基础标准模型】       【Tier 2：复合高危模型】
- 单一解析解/无突变条件         - 多阶段/摩擦力突变/多体耦合
- 阶段 1 & 2 合并推进          - 严格执行 9 阶段全流程
- 自动化快跑测试矩阵           - 双盲推导 + 深度红队审阅
- JEV 快速结构化验证           - 完整 Playwright 实测 + JEV 复核
```

### 3.1 分级判定准则

| 级别 | 模型特征 | 典型示例 | 流程裁剪规则 |
|---|---|---|---|
| **Tier 1<br>(基础标准模型)** | 1. 物理规律存在全局闭式解析解<br>2. 运动过程无离散碰撞、摩擦方向突变或受力跳跃<br>3. 研究对象为单质点/单刚体 | 平抛/斜抛运动、匀速圆周运动、自由落体、竖直上抛、简谐振动单摆、重力场匀强偏转 | 1. 合并阶段 1（物理）与阶段 2（PRD），由 GPT 直接起草定稿。<br>2. Gemini 聚焦教材范围与教学易错点核验。<br>3. 物理测试以解析解公式断言为主。<br>4. GLM 仅提供响应式布局建议。 |
| **Tier 2<br>(复合高危模型)** | 1. 存在多阶段运动（如静动摩擦转换、共速判断）<br>2. 存在多体接触、碰撞或约束耦合<br>3. 场与电路动态自洽耦合（如楞次定律反电动势） | 传送带滑块模型、电磁感应双棒/框架、板块模型、带电粒子复合场、弹簧振子对心碰撞 | **不可裁剪**。必须严格执行阶段 0 至阶段 8 全套 9 个步骤，强制执行 Gemini 双盲推导与 Playwright 自动化数值测试。 |

## 4. 前端物理引擎与交互技术规范

为杜绝 Canvas 动画开发中常见的“数值发散、穿模、共速抖动、高刷模糊、移动端触控冲突”等工程缺陷，阶段 4 编码必须遵循以下规范：

### 4.1 数值计算准则

1. **解析解优先原则（Analytic Solution First）**：
   - 高中物理 90% 以上模型在各自分段区间内拥有解析时间函数 $x = f(t), v = f'(t)$。
   - 动画主循环优先依据“当前阶段起始状态 + 经过时间 $t$”计算确定性解析解，避免让浮点数在每帧累加导致数值发散与能量非物理损耗。
2. **固定时间步长累加器（Fixed Timestep with Accumulator）**：
   - 若模型属于微分方程数值步进类型（如含空气阻力、非线性电磁阻尼），**严禁直接使用 `requestAnimationFrame` 的动态帧间隔 `dt` 作为物理步长**。
   - 必须采用固定物理步长（推荐 $\Delta t = 1/120	ext{ s}$ 或 $1/60	ext{ s}$），使用剩余时间累加器消费步进，确保在 60Hz/120Hz/144Hz 屏幕及卡顿掉帧时物理过程时间流速绝对恒定：
     ```javascript
     let accumulator = 0;
     const FIXED_DT = 1 / 120;
     function loop(timestamp) {
       const frameTime = Math.min((timestamp - lastTime) / 1000, 0.1);
       lastTime = timestamp;
       accumulator += frameTime;
       while (accumulator >= FIXED_DT) {
         physicsStep(FIXED_DT);
         accumulator -= FIXED_DT;
       }
       render();
       requestAnimationFrame(loop);
     }
     ```
3. **临界条件容差带（$\epsilon$-Buffer）**：
   - 在共速判断（$|v_1 - v_2| < \epsilon$）、静摩擦锁死、边界到达判定中，必须设置数值容差 $\epsilon$（建议 $10^{-4}$ 量级），一旦触发即强制状态转移并归一化状态，彻底避免浮点震荡导致的物体高频微小抖动。
4. **守恒量自验看门狗**：
   - 弹性碰撞、绝热振动、无摩擦运动系统，物理计算模块内应内置能量/动量差值计算；若误差超过设定容差（如 $>0.1\%$），在控制台告警并安全钳位。

### 4.2 Canvas 视口与交互响应规范

1. **世界物理坐标系解耦**：
   - 物理计算内部一律采用国际标准单位（米 $	ext{m}$、秒 $	ext{s}$、牛 $	ext{N}$）；
   - 渲染层通过配置 `WorldToScreen` 变换矩阵（含原点、缩放比 $	ext{scalePxPerMeter}$），严禁将屏幕像素数值硬编码进物理更新函数。
2. **高 DPR 锐利化**：
   - 初始化与 `resize` 时强制对齐设备像素比：
     ```javascript
     const dpr = window.devicePixelRatio || 1;
     canvas.width = rect.width * dpr;
     canvas.height = rect.height * dpr;
     ctx.scale(dpr, dpr);
     ```
3. **触控与移动端手势隔离**：
   - Canvas 画布元素必须声明 CSS `touch-action: none;`，并在必要时设置 `e.preventDefault()`，防止用户在画布内拖动物体或调整滑块时引起外部浏览器页面的惯性滚动冲突。
   - 手机视口（390px 档位）下，控制参数区应采用折叠面板或底部悬浮抽屉设计，确保画布至少占据可视高度的 50% 以上。

## 5. 标准制作流程详解

### 阶段 0：选题、查重与通道判定

**执行模型：GPT `opencode-go/gpt-6-luna`；范围与评级由用户确认。**

1. 选定人教版教材模型，记录册、章节、编号及高考拓展标识。
2. 检索 `index.html` 与已有页面，判断属于新增还是现有迭代。
3. 一页仅承载一个物理模型核心机制。
4. **判定复杂度通道**：对照第 3 节标准标明为 **Tier 1** 还是 **Tier 2**。

**产出：**模型卡片（包含模型名称、教材归属、功能范围、分级通道判定及理由）。

---

### 阶段 1：教材考点与物理内核定稿

**执行模型：GPT 起草；Gemini 独立双盲推导（Tier 2 必须，Tier 1 简审）；GPT 汇总定稿。**

1. **GPT 整理物理规格**：
   - 参考系、研究对象、理想化假设；
   - 状态量定义、正方向约定、分阶段动力学/运动学方程；
   - 临界判据、状态机迁移矩阵、守恒量；
   - 易错概念反例及高考典型拓展题型。
2. **Gemini 独立双盲复核**：
   - 不查看 GPT 的现成推导，独立推导方程、核算正负号及量纲；
   - 重点挖掘边界极值（如质量比趋向 $0$ 或 $\infty$、摩擦因数 $\mu=0$、初速度为负）是否存在数学奇点；
   - 标记教材必修/选择性必修原文与竞赛/高考拓展边界。
3. **GPT 意见闭环**：逐条标记“采纳/拒绝/修订”，必须给出定量或推导理由。

**产出：**冻结的物理规格文档。**物理模型未定稿前，严禁编写任何交互与动画代码。**

---

### 阶段 2：PRD 与可量化验收矩阵

**执行模型：GPT 主编；GLM 提供交互草案；Gemini 核查教学重点。**

文档按统一结构编写：
1. 教学演示目标、核心认知障碍点、非目标；
2. 运动状态机（Idle / Running / Paused / Reset / Finished）；
3. 可调参数区间、步长、单位、极值保护规则；
4. 交互操作（单步演进、连续播放、倍速调节、状态回溯）；
5. 矢量箭头（受力、速度、加速度）显示规范；
6. 桌面（1440px）、平板（800px）、移动端（390px）自适应布局；
7. **可量化验收矩阵**：每项用例明确输入参数、解析解预期数值、允许浮点误差门槛。

**产出：**需求与验收矩阵文档（写入主文档）。

---

### 阶段 3：画面与交互方案

**执行模型：GLM 搭建交互草案；GPT 裁决整合；Gemini 审查教学易读性。**

1. 锁定核心视觉元素（静止参考物、运动质点/刚体、场强线、运动轨迹）；
2. 明确矢量图例、数值面板与实时图像（如 $v-t$ 图、$E-t$ 图）的联动时序；
3. 严格遵循 Canvas 与 UI 解耦、DPR 适配与移动端触摸防冲突规范。

**产出：**界面区块划分、参数排布表、状态联动时序表。

---

### 阶段 4：工程实现与代码协作

**执行模型：GPT 为唯一代码整合者；GLM 承担独立组件/补丁；Gemini 仅作静态审阅。**

1. **单页架构**：每个模型为独立 HTML，无服务端依赖，支持本地即开即用。
2. **状态与渲染严格分离**：
   - 物理更新内核：纯数学状态机更新，输入状态与时间步长，输出新状态；
   - 渲染器：只读状态数据并绘制至 Canvas，禁止在绘制中修改物理状态；
   - 暴露全局测试钩子：在 `window` 上挂载测试对象（参见阶段 6）。
3. **代码协作边界**：GLM 只提交局部组件或样式补丁，GPT 审阅差异后合并，严禁并发覆盖同一文件。

**产出：**独立可运行 HTML 页面源码。

---

### 阶段 5：独立代码与物理审阅

**执行模型：Gemini 物理审阅；GLM 代码结构与交互审阅；GPT 实施修复。**

1. 审阅者针对候选代码版本提出具体问题单（文件行号、复现条件、物理影响、修改建议）；
2. GPT 将问题分为阻塞（Blocker）、严重（Major）、次要（Minor），修复后更新修订记录。

---

### 阶段 6：自动化测试与视口验收

**执行模型：GPT 调度自动化脚本执行；Gemini 核查物理用例覆盖完整性。**

#### 6.1 标准化测试钩子与脚本要求

所有页面在开发时必须暴露标准化测试钩子，便于无头环境免交互提取状态：
```javascript
window.__PHYSICS_TEST__ = {
  getEngineState: () => ({ ... }),   // 获取当前坐标、速度、加速度、能量等
  setParameters: (params) => { ... }, // 动态注入测试参数
  step: (dt) => { ... },             // 手动步进指定物理时间
  reset: () => { ... }               // 重置回初始状态
};
```

#### 6.2 自动化测试脚手架执行内容

使用 Playwright 或 Puppeteer 执行自动化测试套件：
1. **物理矩阵验证**：自动注入默认值、上下限极值、反向速度、临界点（如恰好共速、恰好处在脱离临界）；步进指定周期后读取状态，与物理预期数值对比（误差容限 $< 0.1\%$）。
2. **能量/动量守恒断言**：针对守恒系统，断言全程守恒量相对偏差 $< 0.05\%$。
3. **控制台异常监控**：零 Console Error、零未捕获 Promise Rejection。
4. **多视口快照捕获**：
   - 桌面端：1440×900
   - 平板端：800×1024
   - 移动端：390×844
   自动保存截图至 `docs/models/artifacts/<slug>/` 目录供人工核查是否有文字重叠、按钮溢出或 Canvas 裁切。

**产出：**自动化测试机器输出日志（JSON/JUnit 报告）、覆盖率清单及多视口截图。**未执行项坚决标注“未运行”，严禁人工脑补通过。**

---

### 阶段 7：JEV 结构化复核

**执行模型：JEV `jev-1.13`。在阶段 6 自动化测试真实跑通后执行。**

#### 7.1 客观 `state` 构建流水线

为规避 GPT 人工转述产生的过滤效应，必须使用客观材料拼接 `state`：
- **来源 1**：PRD 核心方程与临界判定定义；
- **来源 2**：阶段 6 自动化测试脚本生成的原始 JSON 汇总（用例通过率、最大数值误差、Console 错误数）；
- **来源 3**：物理内核代码关键片段与状态机迁移逻辑。

#### 7.2 评测调用与协议约束

- **端点**：`https://opencode.ai/zen/v1/systemone`；
- **鉴权**：`Authorization: Bearer $OPENCODE_API_KEY`（仅从环境变量读取，严禁写入文档或代码）；
- **问题设计**：
  - `noul`：物理自洽性（`physics_consistent`）；
  - `choice`：风险归类（`issue_type`：物理 / 交互 / 布局 / 无）；
  - `score`：教学直观度与重点呈现（`teaching_clarity`）。
- **结果处理**：读取置信度与概率；当最高概率 $<0.5$ 或存在多义时标为“待人工复核”；**JEV 评分仅作预警雷达，不得替代测试通过判定**。

**产出：**`docs/models/reviews/<slug>-jev.json` 结构化文件。

### 阶段 8：收口、导航与发布交付

1. 页面标题、SEO 标签、公式单位与教材定义核对；
2. 在项目全局 `index.html` 中新增/更新模型卡片；

**最终交付包组成：**
- 独立单页 HTML；
- 主需求与验收文档（`docs/models/<slug>.md`）；
- 阶段 6 自动化测试日志与三端截图；
- 阶段 7 JEV 评测 JSON 结果；
- 导航卡片更新与版本登记。

## 6. 主文档规范与目录结构

为每个物理模型建立唯一事实来源：`docs/models/<slug>.md`。杜绝碎片化会话记录，所有决策与实测数据必须归档于此。

```
project-root/
├── index.html                     # 全局模型导航总索引
├── <slug>.html                    # 各模型独立单页动画（平铺于根目录，一页一模型）
├── <slug>.test.mjs                # 模型测试脚本（与页面同名平铺）
├── tests/<slug>.spec.mjs          # Playwright 自动化测试规格
├── 高中物理动画模型清单.md          # 总清单索引（位于根目录）
├── docs/
│   ├── ai_physics_demo_workflow_v2.md   # 本流程文档（当前有效版本）
│   └── models/
│       ├── <slug>.md              # 单模型全生命周期主文档
│       ├── artifacts/<slug>/      # 自动化测试日志与 3 端截图
│       └── reviews/
│           └── <slug>-jev.json    # JEV 结构化调用与响应证据
└── _repo/                         # 最终静态资源同步副本（独立 Git 仓库）
```

> **目录约定（v2.1 修订）**：模型单页 `*.html` 与其同名测试脚本统一平铺在项目根目录，**不建立 `models/` 子目录**；`_repo/` 为发布同步副本（独立 Git 仓库，不纳入本仓库追踪）。主文档、测试产物与 JEV 证据仍归档于 `docs/models/` 之下。

### 主文档（`<slug>.md`）固定章节模板

